A text description of Algorithm 13 (APPD accelerated by parallel computing):

Algorithm 13 is a parallel accelerated version of Algorithm 4 (MMJ distance by Calculation and Copy). It distributes the computation of the MMJ matrix across multiple threads.

In Variant 1 of Algorithm 13, the task queue initially stores all minimum spanning tree (MST) edge indices in descending order of edge weights. The main thread continuously retrieves tasks from the front of the queue, while worker threads retrieve tasks from the back, enabling simultaneous processing from both directions. The main thread starts with a fully active MST and processes each task by temporarily removing the corresponding edge, computing the two resulting connected components (tree1 and tree2) using DFS, and filling the corresponding entries of the MMJ matrix with the removed edge weight. In contrast, each worker thread starts with an empty active MST and incrementally activates edges according to the task ID it receives, thereby reconstructing the required partial MST by adding edges one by one. After activating the necessary edges, the worker computes the node sets of tree1 and tree2 via DFS and updates all pairwise entries between the two node sets in the MMJ matrix using the associated edge weight.

Variant 2 of Algorithm 13 is a fully worker-driven parallel implementation of Algorithm 4 (MMJ distance by Calculation and Copy), in which all MMJ matrix computations are performed by worker threads, while the main thread only initializes the data structures and launches the workers. The task queue initially stores all minimum spanning tree (MST) edge indices in descending order of edge weights, and each worker thread continuously retrieves tasks from the front of the queue. Unlike Variant 1, every worker thread starts with a fully active MST and progressively removes edges according to the task IDs it receives. After removing the required edges, the worker computes the two connected components (tree1 and tree2) generated by the removed edge using DFS, and then updates all pairwise entries between the two node sets in the MMJ matrix using the associated edge weight. Other variants of Algorithm 13 follow similar parallel processing principles with different task allocation and MST update strategies.

Variant 4 of Algorithm 13 is a fully worker-driven parallel implementation of Algorithm 4 (MMJ distance by Calculation and Copy) based on incremental MST construction. The MST edges are first sorted in ascending order of edge weights, and the task queue initially stores their indices from the smallest to the largest. Each worker thread starts with an empty local MST and continuously retrieves tasks from the front of the shared queue. For a task associated with the k-th MST edge, the worker incrementally adds all preceding edges, from the smallest-weight edge through the (k-1)-th edge, to its local MST, while leaving the current edge uninserted. The two endpoints of the current edge therefore belong to two separate connected components. The worker identifies these components, denoted by tree1 and tree2, using DFS and then assigns the current edge weight to all corresponding pairwise entries between the two node sets in the MMJ matrix. Because each worker preserves its partially constructed local MST between successive tasks and the task indices obtained by a worker increase monotonically, only newly required edges need to be added. All MMJ matrix calculations are performed by the worker threads, while the main thread initializes the data structures, constructs the task queue, launches the workers, and waits for their completion.


Variant 5 is closely related to Variant 4. For each MST edge processed in nondecreasing order of weight, Variant 4 explicitly constructs the forest containing all preceding edges and performs two graph traversals to identify the components connected by the current edge. It then assigns the current edge weight to all cross-component vertex pairs. Variant 5 precomputes the same sequence of component merges as a Kruskal reconstruction tree. Each internal reconstruction-tree node corresponds exactly to one edge-processing task in Variant 4, and its two child subtrees correspond to the two components identified by the traversals in Variant 4. By arranging the original vertices in reconstruction-tree leaf order, these components become contiguous intervals, allowing the corresponding matrix regions to be filled using sequential memory operations. Threads own disjoint output-row ranges, eliminating the dynamic task queue and preventing concurrent writes to the same output row.
